# خطة تصميم واجهة تطبيق تاجر

## الرؤية

تاجر تطبيق عربي واحد يجمع سوقاً اجتماعياً للمنتجات مع أدوات تشغيل حقيقية للتاجر. الأسلوب المطلوب عصري وهادئ وغير ممل، مستوحى من المراجع المرفقة في البطاقات الكبيرة، الصور البارزة، الحواف الدائرية، التنقل السفلي الواضح، والفراغات المريحة، مع استخدام باليت تاجر المعتمدة فقط: Aero وPlummy وPlum Island وMinimal Grey وRiver Styx.

التصميم Mobile-first بامتداد 9:16، RTL، ومناسب للاستخدام بيد واحدة. الأزرار الأساسية كبيرة وواضحة، وعناصر القوائم قابلة للمس بسهولة مع حالات ضغط خفيفة وحركة لا تتجاوز 300ms. ستستخدم جميع الشاشات `ScreenContainer` ومكونات قابلة لإعادة الاستخدام.

## تخطيط الواجهة

يستخدم التطبيق شريطاً سفلياً ثابتاً من أربع أو خمس وجهات بحسب الدور. للزبون: الرئيسية، استكشف، الريلز، المحفوظات، حسابي. للتاجر: الرئيسية، المخزن، الديون، النشر، حسابي. زر الإضافة في المنتصف يظهر كتأكيد بصري فقط حيث تكون الإضافة إجراءً أساسياً.

تحتوي الصفحات الرئيسية على هيدر خفيف، عنوان واحد واضح، ثم شريط بحث مستدير. تستخدم القوائم بطاقات بيضاء أو Plum Island الداكنة، مع صور أو تدرجات تغطي مساحة البطاقة وعناوين فوق طبقة تباين. تستخدم الأزرار الأساسية River Styx أو Plum Island مع نص أبيض، وAero للتأكيدات والنقاط النشطة، بينما تبقى Plummy وMinimal Grey للعناصر الثانوية والحدود الهادئة.

## تدفقات الاستخدام الرئيسية

### الزبون يشتري من بائع

يفتح الزبون الرئيسية، يبحث أو يختار فلترًا، يفتح متجرًا، يختار منتجًا، ثم يضغط اتصال أو دردشة أو واتساب أو حجز. يعرض التطبيق ملخص المنتج وحالة الحجز ويحتفظ بالمحادثة ضمن صفحة التواصل عند توفر الحساب.

### التاجر يدير المخزن

يفتح التاجر لوحة التحكم، يختار المخزن، يبحث عن مادة، يفتح التفاصيل، يعدل الكمية أو يضيف حركة. تظهر حالة النجاح مباشرة وتنعكس في بطاقة المخزن، بينما تعرض الأخطاء على نفس الشاشة دون فقدان الإدخال.

### التاجر يسجل ديناً ودفعة

يفتح دفتر الديون، يختار عميلاً أو يضيف عميلاً، يسجل الدين أو الدفعة، ثم يرى الرصيد الجديد وسجل الحركة. يمكنه إرسال تذكير أو مشاركة كشف من صفحة التفاصيل.

### التاجر ينشر منتجاً أو ريلز

يفتح زر النشر، يختار الصور أو الفيديو، يملأ بيانات المنتج، يرى المعاينة، ثم ينشر. تظهر حالة الرفع والتقدم، ويُحفظ المحتوى في منشوراتي عند النجاح مع إشعار واضح.

## نظام الحركة

تستخدم الشرائح انتقال دخول opacity مع translateY أو translateX خفيف. تستخدم البطاقات opacity عند الضغط، والأزرار scale بين 0.97 و0.98 مع Haptics خفيف للإجراءات الأساسية. الانتقالات بين التبويبات والصفحات قصيرة، وتُعطل الحركات غير الضرورية عند تفعيل `prefers-reduced-motion` أو إعداد تقليل الحركة في التطبيق.

## قرارات البيانات

يُفصل محتوى السوق عن بيانات التشغيل. المنتجات والمنشورات والريلز مرتبطة بملف البائع، بينما المواد والمخزون والديون خاصة بالتاجر المالك. تُستخدم صلاحيات Supabase Row Level Security بحيث لا يرى التاجر إلا بياناته التشغيلية، وتبقى بيانات السوق المنشورة عامة وفق حالة النشر. الوسائط تحفظ في Storage مع مسارات منظمة للمنتجات والمنشورات والريلز وصور الملف.


## قرار دمج حزمة Merchant Operating System — 2026-08-31

الحزمة المرفقة مصدرٌ لبنية التشغيل وليس مصدراً بصرياً. سيتم الاحتفاظ بفكرة المراكز السبعة: الإحصائيات، الطلبات، المخزون، الديون، الدردشة، التنبيهات، وإعدادات المتجر، مع إعادة رسم كل العناصر داخل نظام تاجر الحالي وعدم نقل ألوانها الزرقاء أو بطاقاتها أو تخطيطها كما هو.

| مبدأ المطابقة | تطبيقه داخل تاجر |
|---|---|
| الهوية | اللون الأساسي `#C26243`، خلفية بيضاء/زجاجية، نص `#111827`، حدود هادئة، ورسوم حالة قليلة وواضحة. |
| اللغة | جميع التسميات عبر `I18nProvider` للعربية والكردية والإنجليزية، مع RTL للعربية والكردية وLTR للإنجليزية. |
| التشغيل | تبقى البيانات المحلية الوهمية هي الوضع الافتراضي، وتُنقل عقود Supabase وRealtime إلى طبقة Repository قابلة للتفعيل لاحقاً. |
| التنقل | تبويبات أو قائمة منسدلة متجاوبة؛ لا تُضاف لوحة مستقلة تكرر مسارات المنتجات والمخزون والديون الموجودة. |
| التاجر | يفتح لوحة التشغيل من مسار `/merchant` فقط، بينما تبقى صلاحيات الإدارة العليا خارج هذه الشاشة ومحمية بمسار منفصل. |
| المقاسات | عمود واحد للهاتف، شبكة بطاقات للتابلت، وتخطيط مركزي أعرض للابتوب مع الحفاظ على `ScreenContainer` و`FlatList`. |

تتكون لوحة التشغيل المعتمدة من رأس يحمل اسم المتجر وحالة الحساب والإشعارات، وبطاقة ملخص للمبيعات، ثم مؤشرات الطلبات والمنتجات والمشاهدات والأرباح، ثم اختصارات المخزون والطلبات والديون وإضافة المنتج، ثم نشاط حديث. تفتح كل بطاقة مسارها التفاعلي الحالي، وتظهر حالات التحميل والخطأ والفراغ بدل الصناديق الصامتة. لا يتم استيراد `useMerchantStore` أو عميل Supabase الموجودين في الحزمة مباشرة لأن التطبيق في وضع المعاينة المحلية.

مسار الدمج: تحويل المكونات المفيدة إلى عقود TypeScript صغيرة، ربطها ببيانات المعاينة الحالية، توحيد مكوّنات الحقول والأزرار والحالات، ثم تشغيل اختبارات TypeScript وVitest والتحقق البصري على الهاتف والتابلت واللابتوب قبل اعتماد النسخة.
