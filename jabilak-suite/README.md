# جَايَبْلَك — المشروع الموحد

هذه الحزمة تجمع ثلاث لوحات منفصلة ضمن مساحة عمل واحدة، مع الحفاظ على إعدادات كل لوحة وملفاتها الأصلية:

| اللوحة | المسار | الاستخدام |
|---|---|---|
| لوحة العميل | `apps/customer-panel` | التصفح، المتاجر، المنتجات، وتجربة العميل |
| لوحة التاجر | `apps/merchant-panel` | المنتجات، المخزون، الديون، التحليلات والطلبات |
| لوحة الإدارة | `apps/admin-panel` | إدارة المنصة والإعدادات |

## المتطلبات

يحتاج المشروع إلى Node.js 22 أو أحدث، وpnpm 9، وحساب Supabase إذا أردت تشغيل البيانات الحقيقية. لا توجد مجلدات `node_modules` داخل الحزمة حتى تبقى خفيفة وقابلة لإعادة التثبيت.

## التشغيل في VS Code

افتح مجلد `jabilak-suite` في VS Code، ثم افتح Terminal من جذر المشروع ونفّذ:

```bash
pnpm install:all
```

بعدها انسخ ملف البيئة الخاص بكل لوحة إلى `.env`، وأضف إعدادات Supabase الحقيقية:

```env
EXPO_PUBLIC_SUPABASE_URL=ضع_رابط_مشروعك
EXPO_PUBLIC_SUPABASE_ANON_KEY=ضع_المفتاح_العام
```

لا تضع `service_role` داخل أي تطبيق Expo أو ملف يتم شحنه للمستخدمين.

## فحص المشاريع

```bash
pnpm check
```

لتشغيل لوحة واحدة:

```bash
pnpm dev:customer
pnpm dev:merchant
pnpm dev:admin
```

شغّل لوحة واحدة في كل مرة أثناء المعاينة، أو استخدم منفذًا مختلفًا عبر `EXPO_PORT` عند الحاجة. يمكن أيضًا الدخول إلى مجلد أي لوحة وتشغيل أوامرها المحلية مثل `pnpm android` أو `pnpm ios`.

## Supabase

قبل تجربة التدفقات الحقيقية، راجع وشغّل ملفات SQL الموجودة داخل `apps/merchant-panel/supabase/`. أهم الملفات المضافة هي:

- `20260909120000_merchant_quick_analytics.sql` للتحليلات.
- `20260909123500_order_checkout_flow.sql` لحفظ الطلب، التوصيل، وإعادة حساب الطلب.
- `20260909124500_community_content.sql` للريلز، تجارب العملاء، وقوائم الأمنيات.

يجب أن تكون الجداول مرتبطة بمشروع Supabase الفعلي وأن تكون سياسات RLS مناسبة لبيئة الاختبار قبل الإطلاق.

## ما هو جاهز وما يحتاج استكمالًا

اللوحات الثلاثة موجودة في مشروع واحد وقابلة للفتح والتثبيت والفحص. توجد طبقات جاهزة للتحليلات، الطلبات، الإشعارات، الريلز، التجارب وقوائم الأمنيات. أما البيانات الفعلية، مثل المستخدمين والمنتجات والفيديوهات والأسعار وأجور التوصيل، فلا تُنشأ تلقائيًا؛ يجب إدخالها من Supabase أو من واجهات الإدارة.

قبل إطلاق نسخة تجريبية عامة، يلزم اختبار تسجيل الدخول، سياسات Supabase، رفع الوسائط، الإشعارات على جهاز Android وiOS، وإتمام تدفق الطلب من العميل إلى التاجر. كما أن بعض شاشات المعاينة القديمة قد تحتوي على واجهات محلية تحتاج ربطًا بمستودعات البيانات الفعلية قبل اعتمادها كنسخة إنتاج.

## ملاحظة مهمة

هذه الحزمة لا تحتوي على معلومات وهمية جديدة ولا مفاتيح سرية. أي قيمة غير موجودة فعليًا يجب أن تظهر كغير متاحة، ويجب إدخال الأسعار والمخزون وأجور التوصيل ومحتوى المجتمع من المصدر الحقيقي قبل الاستخدام.

## الثيم المركزي الديناميكي

مصدر الهوية الموحد موجود في `theme.config.js` في جذر المشروع. عدّل `themeColors` لتغيير ألوان لوحات العميل والتاجر والإدارة، وعدّل `fonts` لتغيير عائلات الخطوط. ملفات `apps/*/theme.config.js` تشير إلى هذا المصدر المركزي، وطبقة `useColors` و`Fonts` تقرأ منه تلقائياً.

## مصدر البيانات

تم تجهيز الشاشات لتستخدم Supabase فقط، ولا تحتوي النسخة النهائية على fallback لمنتجات أو متاجر أو إشعارات تجريبية. ضع قيم Supabase الحقيقية في ملفات `.env` الخاصة بكل لوحة اعتماداً على `.env.example`. عند غياب الإعدادات أو البيانات ستظهر حالات فارغة واضحة بدلاً من أرقام أو أسماء وهمية.
