# تقرير استكمال ربط الإدارة والمحادثات بـ Supabase

## سبب ظهور البيانات المحلية والوهمية

كانت شاشات المحادثات تستورد `MOCK_CHATS` و`MOCK_MESSAGES`، وتحتفظ بالقائمة والرسائل داخل `useState`. عند الإرسال كانت الواجهة تضيف الرسالة محليًا ثم تنشئ ردًا تلقائيًا بعد 850ms، لذلك لم تكن الرسائل تصل إلى Supabase ولا تظهر على جهاز أو حساب آخر. وجود جداول `conversations` و`conversation_members` و`messages` في المخطط لا يكفي وحده؛ كان يلزم استدعاؤها من التطبيق.

## ما تم تنفيذه

| الجزء | الحالة |
| --- | --- |
| تحميل قائمة المحادثات | مربوط فعليًا بـ `conversation_members`, `conversations`, `profiles`, و`messages` |
| تحميل الرسائل | مربوط بجدول `messages` مع إخفاء الرسائل المحذوفة |
| إرسال النص | إدراج حقيقي في `messages` |
| إرسال الصور | رفع إلى bucket `chat-media` ثم حفظ مسار المرفق في `messages` |
| إرسال الملفات والمستندات | رفع إلى `chat-media` مع حفظ الاسم والنوع والحجم ومسار الملف |
| التسجيل الصوتي | حفظ رسالة `voice` حقيقية مع مدة التسجيل |
| التحديث الفوري | اشتراك Supabase Realtime على `messages` |
| تحديد الرسائل كمقروءة | تحديث `last_read_at` في `conversation_members` |
| تعديل الرسالة | تحديث حقيقي مع RLS |
| حذف الرسالة | حذف منطقي عبر `deleted_at` |
| حذف المحادثة | طلب حذف حقيقي محمي بسياسة المالك |
| البيانات الوهمية والرد الآلي | أزيلت من شاشات المحادثات |
| لوحة التاجر | بقيت المنتجات والديون مرتبطة بمستودع Supabase الموجود مسبقًا |
| التحقق | `tsc --noEmit` نجح في اللوحتين |

## إعداد مطلوب في مشروع Supabase الفعلي

1. تأكد من تشغيل جداول المحادثات والسياسات الموجودة في `apps/merchant-panel/supabase/schema.sql` على نفس مشروع Supabase المستخدم في اللوحتين.
2. أنشئ bucket خاصًا باسم `chat-media`، ثم طبّق سياسات التخزين الخاصة به الموجودة في المخطط.
3. فعّل جدول `public.messages` في Supabase Realtime من Dashboard أو بتشغيل:

```sql
alter publication supabase_realtime add table public.messages;
```

4. ضع `EXPO_PUBLIC_SUPABASE_URL` و`EXPO_PUBLIC_SUPABASE_ANON_KEY` في إعدادات اللوحتين. لا تستخدم `service_role` داخل تطبيق Expo.
5. أنشئ ملفات تعريف `profiles` للمستخدمين المصادق عليهم؛ لأن عرض اسم الطرف الآخر يعتمد عليها.

## دعم الملفات والمستندات

أضيف نوع `file` إلى `messages` مع الأعمدة `file_name` و`mime_type` و`file_size_bytes`. الحد الأقصى للحجم 25 ميجابايت، ويُحفظ الملف داخل bucket خاص `chat-media` ولا يُستخدم رابط عام. يسترجع التطبيق Signed URL مؤقتًا عند فتح المحادثة.

الترحيل المطلوب هو `20260909130000_message_files.sql` في مساري اللوحتين. زر إرفاق الملف أصبح يرفع المستند ويحفظه فعليًا بدل عرض تنبيه بعدم الدعم.
